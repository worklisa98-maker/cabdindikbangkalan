# Settings Beranda dan data awal lokasi sekolah

Implementasi dan verifikasi: 7 Oktober 2026. Basis source: branch lokal `codex/portal-phase-4-6`, sejajar dengan `origin/Staging` setelah fetch. Tidak melakukan deploy atau import ke database Staging/Production.

1. **Kondisi awal Beranda:** form sudah tersedia di `/admin/settings/landing`, tetapi belum ada akses dari Settings.
2. **Akses baru:** submenu Settings → Beranda menuju form existing. Settings → Lokasi Sekolah menuju section lokasi pada `/user/settings#lokasi-sekolah`. Halaman Settings juga mempunyai card Pengaturan Beranda. Menu/card baru hanya muncul bagi ADMIN_MASTER.
3. **Penyimpanan:** form dan service landing existing tetap digunakan; `site_settings` dengan key `landing_settings` tetap menjadi sumber data. Tidak ada tabel/form duplikat, field statistik manual, atau perubahan API statistik homepage.
4. **Penyebab titik tidak muncul setelah deploy:** migration hanya menyediakan kolom lokasi; membawa workbook ke image tidak menjalankan import ke database target. Sebelumnya hanya CLI yang dapat menulis seed. Audit juga menemukan `.dockerignore` root mengecualikan `backend/`, sehingga build alternatif memakai `Dockerfile.backend` memerlukan ignore file khusus.
5. **Service bersama:** `RunLocationImport` pada `backend/internal/services/school_location_import.go` menggunakan parser existing `ReadLocationSeed`. CLI `--check-db` dan `--apply`, serta API preview/apply, menjalankan service yang sama. Matching hanya NPSN unik; tidak ada INSERT sekolah. Preview memakai transaksi PostgreSQL READ ONLY/REPEATABLE READ. Apply memakai transaksi dan SELECT FOR UPDATE untuk memeriksa ulang kelayakan setelah memperoleh row lock. Kesalahan update/audit menggagalkan seluruh transaksi.
6. **Preview:** `POST /api/admin/master/school-locations/import/preview`. Mengembalikan total baris, koordinat valid, matched, eligible, skipped existing/manual/invalid, not found, errors, dan maksimal 50 contoh lokasi eligible. Matched adalah jumlah kandidat valid yang NPSN-nya ditemukan. Tidak ada pembacaan otomatis saat halaman dibuka.
7. **Apply:** `POST /api/admin/master/school-locations/import/apply`. UI mengaktifkannya setelah preview berhasil dan eligible > 0; ada dialog konfirmasi. Server membaca aset dan memeriksa database lagi. Setelah berhasil, hasil import ditampilkan dan cache lokasi disegarkan. Endpoint tidak menerima file/path dari browser.
8. **Authorization/security/audit:** kedua endpoint berada dalam authGroup existing dan menggunakan pemeriksaan ADMIN_MASTER yang sama dengan landing settings. Role lain ditolak 403; tanpa autentikasi ditolak 401. Proxy Next.js, apiFetch, bearer authentication dan cookie SameSite=Lax mengikuti pola existing. Import API mencatat actor, action `SCHOOL_LOCATION_INITIAL_IMPORT`, count dan timestamp di `admin_audit_log` dalam transaksi yang sama; application log juga mencatat hasil/error. Tidak membuat audit subsystem baru.
9. **Path runtime:** default `assets/data-sekolah-map-bangkalan.xlsx` pada working directory `/app`, sehingga file efektif adalah `/app/assets/data-sekolah-map-bangkalan.xlsx`. Resolver mendukung working directory root repository, backend directory, aset di samping executable, atau `SCHOOL_LOCATION_SEED_PATH` yang hanya dikonfigurasi server. File hilang menghasilkan error dengan `expected path=...` pada log, HTTP 500 dan pesan kegagalan pada UI, bukan sukses 0 baris.
10. **Docker:** kedua Dockerfile existing sudah COPY assets ke final image; instruksi COPY tidak perlu diubah. Ditambahkan `Dockerfile.backend.dockerignore` khusus build dari root agar backend masuk build context. Kedua jalur berhasil dibangun: `docker build -f backend/Dockerfile backend` dan `docker build -f Dockerfile.backend .`. Kedua final image diverifikasi memiliki executable server, workbook yang dapat dibaca, dan working directory `/app`. Test binary Linux yang memakai parser/service proyek dijalankan di kedua image dan berhasil membaca workbook runtime: 144/30/114. Test binary hanya di-bind mount untuk pengujian, tidak ditambahkan ke image produksi. SHA256 workbook di kedua image sama dengan repository: `58c31a0f90f769b579c278ac8ee4437cc01bae611d7fbfa0a53c5c5d34ba1530`.
11. **Dataset:** parsing workbook aktual menghasilkan total 144, valid 30, invalid coordinate 114. Matching pada database fixture terisolasi menghasilkan 30 match. Jumlah matched/eligible di Staging/Production belum diukur; akan ditampilkan oleh Preview Import terhadap database target.
12. **Idempotency:** fixture dengan seluruh koordinat kosong menghasilkan import pertama 30, kedua 0, skipped existing 30. Skenario campuran menghasilkan import pertama 24, kedua 0.
13. **Perlindungan manual:** pengujian mencakup koordinat manual dengan actor, koordinat yang dikosongkan tetapi mempunyai actor/timestamp/source, koordinat existing, dan NPSN tidak ditemukan. Perubahan dilakukan setelah preview untuk membuktikan pemeriksaan ulang saat apply. Koordinat manual -7/112 tetap utuh, row kosong yang diaudit dilewati, dan sekolah baru tidak dibuat. Provenance serta status verified dari workbook tetap mengikuti importer existing; proyek tidak memakai enum EXCEL_SEED. Semua koordinat existing dilindungi, sekalipun source-nya seed.
14. **Validasi:** gofmt; `go test ./...`; `go build ./cmd/server`; integration test PostgreSQL 15 disposable menggunakan tabel TEMP; parser invalid/duplicate/missing asset; HTTP authorization dan missing asset; audit/rollback; update Hero Title dan readback dari site_settings; navigation test seluruh role; location-context test; `npm run lint`; `npx tsc --noEmit`; `npm run build`; kedua build dan pemeriksaan runtime Docker. Semua lulus. Tes database existing yang memerlukan `PORTAL_TEST_DATABASE_URL` tidak dijalankan terhadap target nyata. Belum dilakukan UAT browser dengan login deployment atau verifikasi marker di Staging/Production.
15. **Setelah deploy:** pastikan migration 066 sudah applied, login sebagai ADMIN_MASTER, buka Settings → Lokasi Sekolah → Data Awal Lokasi Sekolah, klik Preview Import, periksa matched/eligible/not-found, lalu Import Data Awal dan konfirmasi. Preview ulang seharusnya menunjukkan 0 eligible untuk baris yang baru diimpor. Periksa marker peta dari API/database target dan uji edit Hero Title lewat Settings → Beranda. Tidak perlu shell atau `go run` di server. Deployment tetap menggunakan konfigurasi database target yang benar.

Pengujian integrasi dapat diulang dengan `LOCATION_IMPORT_TEST_DATABASE_URL` menuju PostgreSQL disposable, lalu `go test ./internal/services -run TestLocationImportIntegration -v` dari backend. Test menggunakan tabel TEMP yang terikat satu koneksi dan tidak memodifikasi tabel sekolah/settings existing.
